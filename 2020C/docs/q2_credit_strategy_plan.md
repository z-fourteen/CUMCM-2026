# 第二问信贷策略说明

第二问在第一问模型基础上处理附件 2 的 302 家无信贷记录企业。由于附件 2 没有信誉评级和历史违约标签，本问不采用机器学习，而是采用“第一问阈值迁移 + 经营数据评分 + 估计信用等级 + 1亿元授信分配”的可解释策略。

## 一、风险评估

### 1. 规则迁移

第二问沿用第一问的数据清洗和指标构造口径：

- 有效销项发票计入真实营业收入。
- 有效进项发票计入经营成本。
- 作废发票不计入收入成本，但计入作废率。
- 负数发票参与金额抵减，并计入负数率。
- 日期转为月份，计算经营月份、断档和收入波动。

与第一问不同的是，附件 2 没有 `信誉评级` 和 `是否违约`，因此不能直接使用信用历史信息。模型先使用附件 1 计算得到的分位数阈值作为银行已有授信经验，再迁移到附件 2。

### 2. 基础门槛

附件 2 的一票否决条件全部来自经营数据：

| 门槛 | 脚本指标 | 数值阈值 |
| --- | --- | ---: |
| 无正常销项交易 | `有效销项发票数` 或 `有效销项金额` | 为 0 |
| 有效销项金额过低 | `有效销项金额` | 小于等于附件 1 的 5% 分位 |
| 有效经营月份过少 | `有效经营月份数` | < 6 |
| 作废率极端异常 | `最大作废率=max(销项作废率,进项作废率)` | > 40% |
| 负数率极端异常 | `最大负数率=max(销项负数率,进项负数率)` | > 30% |
| 进销严重不匹配 | `进销匹配差异=abs(有效进项金额/有效销项金额-1)` | > 4 |

这些门槛不使用附件 2 自身的评级信息，因为附件 2 不存在真实评级；也不使用机器学习标签预测，避免用小样本监督模型制造虚假的精度。

### 3. 量化打分卡

第二问继续使用第一问的五维评分卡：

```text
信用得分 =
0.25 * 经营规模分
+ 0.20 * 经营连续性分
+ 0.25 * 交易真实性分
+ 0.20 * 抗风险能力分
+ 0.10 * 信用基础分
```

前四项的具体指标与第一问一致：

| 维度 | 子指标 |
| --- | --- |
| 经营规模分 | `有效销项金额`、`月均销项收入`、`毛利率` |
| 经营连续性分 | `有效经营月份数`、`最长销项断档月数`、`销项收入波动系数` |
| 交易真实性分 | `最大作废率`、`最大负数率`、`进销匹配差异` |
| 抗风险能力分 | `客户数`、`供应商数`、`客户集中度HHI`、`供应商集中度HHI` |

由于缺少真实评级，第五项 `信用基础分` 改为由经营综合预评分推断：

```text
经营综合预评分 =
0.30 * 经营规模分
+ 0.25 * 经营连续性分
+ 0.25 * 交易真实性分
+ 0.20 * 抗风险能力分
```

再按附件 2 企业内部排序生成估计信用等级：

| 经营综合预评分位置 | 估计信用等级 | 信用基础分 |
| --- | --- | ---: |
| 前 15% | 类A | 90 |
| 15% 至 40% | 类B | 75 |
| 40% 至 75% | 类C | 60 |
| 后 25% | 类D | 30 |

这里的 `估计信用等级` 只是模型推断的相对信用层级，不等同于银行真实评级。

### 4. 风险等级与分级原因

最终风险等级仍只保留四类：

| 信用得分 | 最终风险等级 |
| ---: | --- |
| >= 80 | 低风险 |
| >= 65 且 < 80 | 较低风险 |
| >= 50 且 < 65 | 中风险 |
| < 50 | 高风险 |

高风险池是过程标记，不作为最终风险等级。进入高风险池的条件为：

- 信用得分 < 50。
- 最大作废率 > 25%。
- 最大负数率 > 15%。
- 进销匹配差异 > 2.5。

客户集中度 HHI 和供应商集中度 HHI 不单独作为高风险池条件，因为它们已经在 `抗风险能力分` 中以连续扣分方式体现。这样可以避免同一集中度风险既降低信用得分、又额外触发高风险池的重复惩罚。

结果表输出 `分级依据指标`，包含信用得分、有效销项金额、毛利率、有效经营月份、最大作废率、最大负数率、进销匹配差异、客户HHI和供应商HHI，用于解释每家企业的分级原因。

## 二、放贷策略

### 1. 年度总额

第二问题设年度信贷总额固定为：

```text
10000 万元
```

脚本默认即按 1 亿元输出最终授信策略。

### 2. 贷款额度

通过基础门槛的企业先计算：

```text
初始建议额度 = 10 + 90 * 信用得分 / 100
```

然后按最终风险等级限制额度：

| 风险等级 | 额度区间 |
| --- | ---: |
| 低风险 | 70 至 100 万元 |
| 较低风险 | 40 至 80 万元 |
| 中风险 | 10 至 50 万元 |
| 高风险 | 10 至 30 万元 |
| 高风险池 | 不改变最终风险等级，但额度上限压缩至 30 万元 |
| 一票否决 | 0 万元 |

资金分配顺序为：

```text
风险等级优先
-> 非高风险池优先
-> 信用得分高优先
```

若 1 亿元没有用满，则从低风险企业开始追加至额度上限；若全部可授信企业都达到额度上限仍未用满，则保留剩余额度，不突破风控上限。

### 3. 贷款利率

利率区间按最终风险等级确定：

| 风险等级 | 利率区间 |
| --- | ---: |
| 低风险 | 4% 至 7% |
| 较低风险 | 7% 至 10% |
| 中风险 | 10% 至 12% |
| 高风险 | 12% 至 15% |

附件 3 的客户流失率曲线需要评级，因此本问按估计信用等级映射：

| 估计信用等级 | 使用附件 3 曲线 |
| --- | --- |
| 类A | 信誉评级 A |
| 类B | 信誉评级 B |
| 类C | 信誉评级 C |
| 类D | 信誉评级 C |

在候选利率区间中选择 `贷款利率 * (1 - 客户流失率)` 最大的利率，作为建议贷款年利率。

### 4. 可行性测试

除默认 1 亿元结果外，脚本额外测试：

```text
5000万元、8000万元、10000万元、12000万元、15000万元、20000万元
```

用于说明该策略在不同资金规模下是否能用满额度，以及资金过大时剩余额度产生的原因。
